# Billing, UI and preview audit — September 24, 2026

Scope: unified draft PR #18 only. No production schema changes, customer updates,
notifications, charges, imports or Vagaro changes. This checkpoint does not replace
the hosted-schema recovery and stabilization launch gates.

## Regressions found and corrected

- Release `8f9dd4de8404c10f519f6cd84a2a25e4b8ee1803` still failed CI.
  The client editor had literal backslash-n text in an import and JSX. Restored
  its last parseable blob and moved the action center to the authenticated server
  profile page. Existing profile/plan editing remains; booking, messaging and
  owner checkout now retain the selected client instead of opening generic lists.
- Client Billing History filtered `paid`, but the ledger writes `succeeded`.
  Shared payment presentation now handles successful, pending, failed and refund
  rows. Malformed amounts/statuses are held out of totals and shown for review.
- Payment totals previously combined currencies and implied the capped list was
  lifetime history. Totals now remain per currency, refunds are separate, and the
  100-record client/8-record owner scopes are disclosed. No account balance,
  money owed, receipt delivery or plan activation is inferred from these totals.
- Failed payment reads previously looked like empty history. They now show an
  unavailable state and suppress misleading zero metrics. Checkout verifies the
  active owner before creating a service client or reading the client roster.
  Client payment reads keep explicit user ownership filtering plus existing RLS.
- The financial snapshot silently converted failed queries to zero, used fixed
  UTC-7 in winter, and could stop at the first database page. Queries now page,
  fail visibly, use the existing Pacific converter, and bound completed sessions
  by the current instant. Plan/rental/package values are labeled operating
  estimates, not collected cash. Existing estimate arithmetic is otherwise retained.
- Checkout's `success=1` URL claimed payment and activation. It now only indicates
  return from Stripe and points to recorded payments. Catalog prices are not
  loaded here; the UI directs review in Stripe instead of showing stale prices.
  Product controls remain keyboard-disabled until a real roster client is chosen.
- Vercel's PR #18 comment explicitly rejected `0 */2 * * *` on its daily-only
  cron plan (comment 5815836482). Restored `0 16 * * *` for deployable previews.
  This is NOT acceptance of daily reminder coverage for launch. No plan upgrade
  or alternate scheduler has been purchased/enabled.

## Verification

`tests/billing-ui-audit.test.cjs` adds synthetic regression coverage for payment
states, refunds, currencies/minor units, Pacific dates, auth-before-read, explicit
client scoping, error/empty separation, record caps, checkout notices and controls,
financial pagination and winter boundaries. A whole-application TypeScript parse
check catches malformed injected escapes before lint/build. The tests do not call
hosted Supabase, Stripe, Resend or any real client account.

Local focused verification is not complete hosted RLS or browser acceptance.
Require the exact resulting commit's full GitHub quality gate and Vercel READY
preview before claiming code/build readiness. A READY preview remains distinct
from migration rehearsal, provider verification and production deployment.
