# Consolidated exercise, program and video cleanup

## Baseline
Starting release head: fb598d1eb830a3843a59509737966ceb43aae731. Its CI was failing the client record/upload control test. Earlier syntax repairs had not established a working end-to-end capture flow.

## Findings and corrections
- Read-only hosted schema inspection found the new exercise API wrote nonexistent programming_notes/video_provider/video_url fields and an invalid movement-pattern enum. Capture now uses verified short_description, setup_notes, default prescription columns, video_guid and valid enum values.
- Client selection previously was only text metadata. It now creates a real, linked, PRIVATE quick-program draft, preserving the exercise ID and prescription. Raw client identifiers are not stored on reusable exercise rows.
- Exercise and optional client draft are two replay-safe saves, NOT a single database transaction. Stable IDs, owned content fingerprints and explicit partial-success errors permit retry without duplicate exercise creation.
- Converted exercise sets were JSON snapshots while the old screen looked only for program_exercises rows. A source-aware entry point opens the actual saved snapshots with bounded, concurrent-edit-protected prescription editing. The original renderer is preserved intact for existing generated/manual programs.
- Generic PATCH cannot publish or rewrite quick-library draft source. This pass does NOT implement or authorize client release of quick drafts.
- Custom exercises are visible in a recent-capture section and can reopen with descriptions/defaults and protected video playback. Canonical source catalog counts and approval records are unchanged.
- Exercise video uploads use deterministic, validated private coach/exercise paths. Actual stored file size/type is checked before attaching. Short-lived playback is separately authorized. Signed URLs are not stored as permanent public media links.
- Client recording and upload are actual separate controls, with preview, error handling and truthful notification status. Client clip saves verify the folder/file, use stable media IDs, and avoid duplicate notification on replay.
- Original video upload remains the default. Optional browser optimization preserves portrait/landscape framing, never upscales, and retains the original on audio/decode/encode failure. Optimization is explicitly 30 fps, not a 60 fps/high-motion promise. Browser audio, HEVC/HDR and device playback still require real-device QA.
- Whole-repository JS/TS parsing now aggregates all source/test/script syntax errors before tests. No blind global replacement of escape sequences.

## Verification boundary
Local dependency-light tests cover validation, known schema columns, replay/concurrent create, partial failure/recovery, missing/deleted clients, private path ownership, source identity, prescription edits, publication bypass prevention, unauthorized/cross-origin calls and video dimensions. The full GitHub regression/lint/build/typecheck result must be verified for the final SHA, not inferred from these local tests.

No production migrations, client/package/payment edits, real video uploads, email/SMS tests, main merge or production promotion were performed in this cleanup. Read-only schema checks are not hosted workflow acceptance.
